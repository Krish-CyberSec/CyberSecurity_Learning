## 1. Prerequisites

Before starting, make sure you have:

- [ ] A Windows Server machine to use as the Domain Controller (DC).
- [ ] A Windows client machine that will join the domain.
- [ ] Administrator access on both machines.
- [ ] Network connectivity between the server and client.
- [ ] A planned domain name, for example `xyz.com`.
- [ ] A static IP address planned for the Domain Controller.

### Example values used in this guide

Replace these example values with the values from your own lab.

| Setting | Example |
|---|---|
| Domain name | `xyz.com` |
| Domain Controller hostname | `DC01` |
| Domain Controller static IP | `192.168.1.10` |
| Client hostname | `CLIENT01` |
| Domain administrator | `XYZ\Administrator` |

> **Important:** Keep your domain name, server IP, interface index, and credentials consistent throughout the setup. Do not copy the example values blindly.

## 2. Enable PowerShell Remoting

PowerShell Remoting allows you to run PowerShell commands remotely between Windows machines.

Run PowerShell as **Administrator** on the machine where you want to enable remoting:

```powershell
Enable-PSRemoting -Force
```

### Microsoft reference

https://learn.microsoft.com/en-us/powershell/module/microsoft.powershell.core/enable-psremoting?view=powershell-7.6

## 3. Configure Trusted Hosts

For the workgroup / non-domain setup described in this lab, add the Windows Server to the client's TrustedHosts list and add the client to the server's TrustedHosts list.

In other words:

```text
Client TrustedHosts  → Windows Server
Windows Server TrustedHosts → Client
```

Configure the entries on the respective machines, using the actual computer name or address required by your lab.

### Reference

https://techdirectarchive.com/2020/03/23/how-to-add-servers-to-the-trusted-hosts-list/

> **Note:** TrustedHosts is a WinRM client-side trust setting. Use it only for systems you trust in your lab. Prefer domain-based authentication and appropriately secured remoting in a production environment.

## 4. Prepare the Domain Controller

On the Windows Server that will become the Domain Controller, open the Server Configuration tool:

```cmd
sconfig
```

Use `sconfig` to configure the following:

1. **Computer name:** Set the server hostname, for example `DC01`.
2. **Network settings:** Assign a static IP address.
3. **DNS server:** Set the server's DNS address to its own static IP address.

Restart the server if prompted after changing the hostname or network configuration.

### Record the server network details

Keep these values available for the client configuration:

```text
Domain Controller hostname:
Domain Controller FQDN:
Domain Controller static IP:
Domain name:
```

Example:

```text
Hostname: DC01
FQDN: DC01.xyz.com
Static IP: 192.168.1.10
Domain: xyz.com
```

## 5. Install Active Directory Domain Services

Run the following commands in an elevated PowerShell session on the Windows Server.

### Step 1 — Install the AD DS role

```powershell
Install-WindowsFeature -Name AD-Domain-Services -IncludeManagementTools
```

### Step 2 — Import the deployment module

```powershell
Import-Module ADDSDeployment
```

### Step 3 — Promote the server to a Domain Controller

```powershell
Install-ADDSForest
```

You will be prompted to provide the domain name. For example:

```text
xyz.com
```

The promotion process will also ask for the Directory Services Restore Mode (DSRM) password. Set and securely store this password.

The server may restart after the promotion process completes.

### Microsoft reference

https://learn.microsoft.com/en-us/windows-server/identity/ad-ds/deploy/install-active-directory-domain-services--level-100-

## 6. Configure Client DNS

Before joining the domain, configure the **client machine's DNS server address** to point to the Domain Controller.

Active Directory domain discovery relies on DNS. The client should use the Domain Controller's IP address as its DNS server.

### Step 1 — Identify network interface details

Run on the client:

```powershell
Get-NetIPAddress
```

Identify the interface index for the network adapter connected to your lab network.

### Step 2 — Inspect DNS server configuration

```powershell
Get-DnsClientServerAddress
```

### Step 3 — Set the DNS server address

Replace the interface index and server address with your actual values:

```powershell
Set-DnsClientServerAddress -InterfaceIndex "<INTERFACE_INDEX>" -ServerAddresses "<DOMAIN_CONTROLLER_IP>"
```

Example:

```powershell
Set-DnsClientServerAddress -InterfaceIndex "12" -ServerAddresses "192.168.1.10"
```

In this example:

- `12` is the client network adapter's interface index.
- `192.168.1.10` is the Domain Controller's static IP.

### Verify DNS configuration

```powershell
Get-DnsClientServerAddress
```

Confirm that the client is using the Domain Controller's IP address for DNS.

## 7. Join the Client to the Domain

Run the following command in an elevated PowerShell session on the client machine.

```powershell
Add-Computer -DomainName "xyz.com" -Credential "XYZ\Administrator" -Force -Restart
```

Replace:

- `xyz.com` with your actual Active Directory domain.
- `XYZ\Administrator` with the appropriate domain account.

You will be prompted for the account password. The client will restart after a successful domain join.

> **Reminder:** The domain name and account prefix must match the domain you created. For example, if your domain is `DMC.com`, use the corresponding domain account rather than the `XYZ` example above.

## 8. Verify the Setup

After the client restarts, sign in using a domain account.

Useful checks:

### Check the computer's domain membership

```powershell
(Get-CimInstance Win32_ComputerSystem).Domain
```

### Check the computer name and domain membership status

```powershell
Get-CimInstance Win32_ComputerSystem | Select-Object Name, Domain, PartOfDomain
```

### Check DNS server configuration

```powershell
Get-DnsClientServerAddress
```

The client should show the Domain Controller's IP as its DNS server, and `PartOfDomain` should be `True`.

## Notes

- Run administrative commands from an elevated PowerShell session.
- Use a static IP for the Domain Controller so clients can reliably find its DNS service.
- Point domain clients to the Domain Controller for DNS.
- Use your own lab's interface index, IP addresses, domain name, and credentials.
- Keep the DSRM password and domain administrator credentials secure.
- The TrustedHosts step is included because it is part of this lab's initial remoting setup; it is not a replacement for secure authentication and transport configuration in production.
